# 商品识别量化与多模态方案调研

日期：2026-06-16  
用途：6.18 甲方会议第三部分扩展材料

## 1. 总体判断

甲方提出的“把感性设计洗成量化特征，形成商品基因库”方向有价值，尤其适合补充当前预测模型的冷启动短板。

但第一阶段不建议直接训练一个视觉模型来预测销量。更合理路线是：

```text
商品图片/设计文本
  -> 多模态模型抽取结构化标签
  -> 人工复核少量关键标签
  -> 建商品基因表
  -> 做相似款生命周期曲线和冷启动先验
  -> 再评估是否接入预测模型
```

原因：

- 260 个 SKU 对训练视觉模型来说样本太少；
- 260 个 SKU 足够做一版标签体系、API 标注流程和业务验证；
- 设计标签是商品上市前就能拿到的静态信息，不会造成未来信息泄漏；
- 当前模型最大短板之一是新品冷启动，商品基因标签正好可以补这一块。

## 2. 推荐技术路线

### 2.1 V0：多模态大模型 API 批量打标

输入：

```text
商品主图
细节图
模特图 / 平铺图
sku_id / style_id
品类
季节
吊牌价
已有商品文案
```

调用多模态大模型 API，让模型按照固定 JSON schema 输出标签：

```json
{
  "style_id": "xxx",
  "sku_id": "xxx",
  "category": "pants",
  "color_family": "black",
  "saturation_level": "low",
  "silhouette": "wide_leg",
  "fit_level": "loose",
  "fabric_handfeel": "drapey",
  "fabric_weight": "medium",
  "structure_type": ["curved_panel", "asymmetric_cut"],
  "design_complexity": "medium",
  "style_keywords": ["minimal", "relaxed", "designer"],
  "occasion": ["commute", "daily"],
  "confidence": 0.82,
  "needs_human_review": true
}
```

优点：

- 不需要训练数据，最快能落地；
- 适合先把 260 个 SKU 跑通；
- 可以快速形成商品基因表；
- 可以保留模型版本、prompt 版本、置信度，便于复核。

风险：

- 标签一致性不一定稳定；
- 对细粒度服装术语可能会误判；
- 需要人工抽检或复核关键标签；
- 不同 API 供应商输出风格可能不同，必须固定 schema 和 prompt。

当前判断：

```text
非常适合 V0。
```

### 2.2 V1：API 预标注 + 人工复核

这是最推荐的正式 V1 路线。

流程：

```text
多模态 API 初标
  -> 低置信度/关键 SKU 人工复核
  -> 标签字典归一
  -> 商品基因表入库
  -> 与订单/库存/补货/利润数据关联
```

人工复核重点：

- 品类；
- 廓形；
- 版型松紧；
- 面料手感；
- 结构类型；
- 设计复杂度；
- 风格关键词；
- 使用场景。

为什么要人工复核：

- 服装设计标签很主观；
- “弯刀结构”“垂坠面料”“低饱和色”“法式松弛”这类词需要品牌内部定义；
- 甲方后续真正要用的是稳定标签体系，而不是一次性模型描述。

建议输出：

```text
product_gene_table.csv
product_gene_dictionary.csv
product_gene_label_audit.csv
```

### 2.3 V2：视觉 embedding + 相似款检索

不一定只做解释标签，也可以并行做相似款检索。

流程：

```text
商品图片
  -> 多模态/视觉 embedding
  -> 向量库
  -> 对新款检索 TopK 历史相似款
  -> 聚合历史相似款的生命周期曲线
```

业务输出：

```text
该新款最像历史哪些款
这些相似款上市后第1-4周补货曲线
第5-8周是否继续增长
是否长尾
是否容易断崖下跌
历史相似款平均大货概率
```

优点：

- 对冷启动非常直接；
- 不完全依赖人工标签；
- 可以和结构化标签互补。

缺点：

- 可解释性弱于人工标签；
- 相似不等于同样卖得好；
- 需要有足够历史商品图片和历史表现。

### 2.4 V3：微调或训练视觉模型

不建议当前直接做。

适合训练的前提：

```text
至少几千个历史商品
每个商品有稳定图片
有人工复核标签
有销售/补货/售罄/退货结果
有清晰训练目标
```

可能训练的任务：

1. 多标签分类  
   预测颜色、廓形、结构、风格、场景等标签。

2. 相似款 embedding 微调  
   让同类设计语言、类似生命周期表现的商品向量更近。

3. 业务结果预测  
   用图片 + 商品属性预测生命周期曲线、冷启动销量分层、大货概率。

当前 260 个 SKU 的问题：

- 样本太少，训练容易过拟合；
- 很难覆盖所有品类、颜色、结构和风格组合；
- 业务标签可能还没有统一；
- 如果直接预测销量，噪声会很大。

因此建议：

```text
260个SKU用于验证标签体系和API流程；
不要用于从零训练模型。
```

## 3. API 路线和训练路线对比

| 路线 | 数据要求 | 成本 | 速度 | 可解释性 | 当前推荐 |
| --- | --- | --- | --- | --- | --- |
| 多模态 API 零样本打标 | 图片+schema | 中 | 快 | 中高 | 推荐 V0 |
| API + 人工复核 | 图片+少量人工 | 中 | 中 | 高 | 最推荐 V1 |
| 视觉 embedding 检索 | 图片+历史商品库 | 中 | 中 | 中 | 推荐并行探索 |
| 微调标签分类器 | 几千标注样本 | 高 | 慢 | 高 | 后续再做 |
| 端到端销量预测 | 大量图片+销售标签 | 很高 | 慢 | 低到中 | 当前不建议 |

## 4. 对当前补货预测模型的帮助

### 4.1 冷启动

当前冷启动问题：

```text
新品没有历史订单
没有历史库存
没有 Event
没有求购
模型只能靠类目、价格、首单等弱特征猜
```

商品基因表能提供：

```text
这个新款像哪些历史款
这些历史款第几周起量
是否长尾
是否容易断崖下跌
是否容易成为大货
```

可构造特征：

```text
similar_style_topk_mean_qty_30d
similar_style_topk_positive_rate
similar_style_topk_blockbuster_rate
similar_style_topk_decay_slope
gene_group_lifecycle_week3_5_peak_rate
gene_group_tail_strength
gene_group_zero_risk
```

### 4.2 生命周期曲线

按商品基因分组后，可以计算：

```text
上市后第1周需求
第2周需求
第3-5周爆发概率
第6-12周长尾强度
生命周期末期衰退速度
```

这对现在缺少完整生命周期字段的问题有帮助，但不能完全替代 `b2b_launch_date` 和 `off_shelf_date`。

### 4.3 大货识别

商品基因可以作为大货先验：

```text
某些结构/面料/颜色/风格组合历史上更容易成为大货
某些重设计款更可能短期爆发但快速衰退
某些基础款更可能稳定长尾
```

这可以服务 Phase8/Phase9 的 `blockbuster_under_wape` 优化。

## 5. 对盈亏分析模块的帮助

商品基因表不是直接算利润，但可以影响风险假设：

```text
设计复杂度高 -> 需求波动更大
基础款/常青款 -> 长尾更稳
高饱和色/强设计 -> 滞销或退货风险可能更高，需要数据验证
强季节款 -> 生命周期窗口更短
```

可用于盈亏模块：

- 调整需求场景宽度；
- 调整保守/激进策略；
- 给高波动款增加风险惩罚；
- 给基础长尾款放宽剩余库存惩罚；
- 作为生产决策解释字段。

注意：

> 这些规则必须通过历史数据验证，不能仅凭设计常识直接写死。

## 6. 对五个甲方场景的详细判断

### 场景 1：补货预测衰退周期

可做，且最值得做。

实现方式：

```text
商品基因标签
  -> 历史相似款分组
  -> 计算生命周期曲线
  -> 生成冷启动先验
  -> 加入预测模型或作为后处理解释
```

短期产出：

- 新款相似历史款 TopK；
- 相似款平均补货曲线；
- 大货概率；
- 长尾强度；
- 衰退速度。

### 场景 2：买手级智能推盘

中期可做。

需要额外数据：

```text
buyer_id/store_id
历史订货SKU
订货数量
后续售罄率
后续补货量
退货/滞销情况
买手店区域/等级/风格定位
```

如果只有买手订货，没有终端售罄或销售表现，只能学“买手偏好”，不能学“买手买了之后是否卖得好”。

### 场景 3：商品企划复盘

短期很适合。

不一定需要复杂模型，先做分析报表：

```text
标签 x 补货量
标签 x 售罄率
标签 x 毛利
标签 x 库存剩余
标签 x 生命周期长度
```

这部分对甲方最容易理解，也能形成商品企划语言。

### 场景 4：退货归因

当前不优先。

需要数据：

```text
return_date
sku_id
buyer_id/store_id
return_qty
return_reason
refund_amount
original_order_id
```

没有退货数据时，不建议承诺“退货归因”。

### 场景 5：企划防撞车

可以做演示。

实现方式：

```text
商品标签相似度
图片embedding相似度
价格带相似度
品类/波段/场景相似度
```

输出：

```text
SKU相似度矩阵
高重合SKU对
可能互相分流的商品组合
建议保留/区分/调整
```

这更像企划工具，不是当前预测模型的核心优化。

## 8. 评估方式

商品基因表是否有价值，不能只看标签是否“看起来准”，要看业务指标。

建议三类评估：

1. 标签一致性
   ```text
   同一SKU多次打标是否稳定
   人工和模型标签一致率
   低置信度标签占比
   ```

2. 相似款有效性
   ```text
   TopK相似款的历史曲线是否能解释新品曲线
   相似款先验相比类目均值是否更准
   ```

3. 模型增益
   ```text
   不加商品基因特征 vs 加商品基因特征
   冷启动 WMAPE
   blockbuster_under_wape
   true=0误报率
   排序相关性
   ```

## 9. 建议会议口径

可以这样说：

> 商品识别量化方向我们认为很有价值，尤其对新品冷启动和相似款生命周期预测有帮助。但当前 260 个 SKU 不适合直接训练视觉销量模型。更稳妥的做法是先用多模态大模型 API 按固定标签体系批量打标，再做人工复核，形成商品基因表。第一阶段重点验证它能不能提升冷启动预测、相似款曲线和商品企划复盘；如果后续积累到更多历史商品和稳定标签，再考虑训练或微调视觉模型。

## 10. 推荐阶段计划

| 阶段 | 时间 | 目标 | 产出 |
| --- | --- | --- | --- |
| V0 | 1-2周 | 260 SKU API 打标试跑 | 商品基因表草稿、标签一致性报告 |
| V1 | 2-4周 | 人工复核和标签字典稳定 | 可入库商品基因表、相似款检索 demo |
| V2 | 4-8周 | 接入预测 shadow 实验 | 冷启动/生命周期曲线增益报告 |
| V3 | 后续 | 数据量扩大后训练或微调 | 专用标签模型或相似款 embedding |

## 11. 成本补充

260 个 SKU 规模下，API 费用不是主要成本。建议预算口径：

| 档位 | 内容 | 粗估 |
| --- | --- | ---: |
| Demo | API 打标 + 抽检 + CSV/Excel | 1,000-8,000 RMB |
| V1 | API + 人工复核 + 入库 + 审计 | 1万-5万 RMB |
| V2 | V1 + 相似款检索 + 预测 shadow 实验 | 3万-8万 RMB |

不建议当前直接训练视觉模型，原因是样本量和标签体系都不够稳定。详细成本调研见：

`reports/current/client_meeting_20260618_multimodal_cost_research.md`
