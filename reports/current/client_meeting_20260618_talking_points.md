## 3. 盈亏模块 4 分钟

核心口径：

> 盈亏分析模块不是重新预测销量，而是接在预测模型后面，把“未来可能补多少”转换成“现在是否值得生产、生产多少、分到哪些SKU”。

必须强调：

```text
预测量 != 推荐生产量
```

模块已完成：

```text
预测输入
-> 概率/需求场景校准
-> SKU聚合到SKC
-> 库存和成本拼接
-> SKC候选生产量
-> 多场景利润模拟
-> 风险评分
-> SKC推荐量
-> SKU分配
-> 质量报告和运行清单
```

可以讲真实回测：

| 策略 | 正计划数 | 总生产量 | 有利 | 有害 | 相对不补货实验利润 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 直接按预测缺口 | 210 | 21,000 | 6 | 204 | -3,914,626 |
| 盈亏模块 | 3 | 300 | 3 | 0 | +130,980 |

解释：

> 这个不是说预测模型真实亏了 391 万，而是历史反事实回测。它说明如果不经过盈亏过滤，直接把预测缺口转成生产计划，最小生产批量会放大过补风险。盈亏模块的价值是过滤风险，只保留少量高确定性的生产建议。

需要甲方配合：

```text
每个SKC生产周期
MOQ和生产递增粒度
已下生产单/在途/预计入仓日期
真实成本
实际成交价或统一结算折扣
人工最终决策和修正原因
```

## 4. 商品识别量化 3 分钟

核心口径：

> 商品识别量化方向是有价值的，但第一阶段不建议直接承诺“用图片精准预测销量”。更合理的是先用多模态大模型 API 把图片和设计语言转成商品基因表，再通过人工复核保证标签稳定，最后用于新品冷启动、相似款生命周期曲线和商品企划复盘。

五个场景判断：

| 场景 | 判断 |
| --- | --- |
| 补货预测/衰退周期 | 最值得先做，帮助冷启动 |
| 买手级推盘 | 有价值，但需要买手销售/售罄数据 |
| 商品企划复盘 | 很适合先做，偏分析报表 |
| 退货归因 | 需要退货数据，暂不优先承诺 |
| 企划防撞车 | 可以做相似度矩阵演示 |

建议落地：

> 先做商品基因表，字段包括颜色、饱和度、廓形、版型、面料、结构、设计复杂度、风格关键词、场景、标签来源和置信度。

技术路线：

```text
V0：多模态API批量打标260个SKU
V1：人工复核关键标签，稳定标签字典
V2：做相似款检索和冷启动shadow实验
V3：等历史商品和人工标签足够后，再考虑训练/微调视觉模型
```

要说清楚：

```text
260个SKU适合验证标签体系和API流程
不适合从零训练一个稳定视觉销量模型
```

成本口径：

> 260 个 SKU 规模下，多模态 API 的直接费用不是主要成本，一次性打标通常是几十到几百元人民币级别。真正要投入的是人工复核、标签字典、批量处理脚本、入库审计和后续 shadow 实验。如果只做 Demo，大致是 1,000-8,000 元；如果做可入库的 V1，大致是 1万-5万；如果继续做相似款检索和预测验证，大致是 3万-8万。训练视觉模型至少 5万-20万起步，而且当前 260 个 SKU 样本不够，所以不建议现在做。

需要甲方确认：

```text
商品图片是否允许发给外部多模态API
是否必须国内云或私有化部署
是否能提供主图、细节图、模特图、平铺图
是否有历史老款图片和设计/企划人员参与复核
最先验证目标是冷启动预测，还是企划复盘/防撞款演示
```

## 5. 特殊节点 4 分钟

甲方问题：

> 误差大的商品存在直播爆款、节日等因素，现在是否有字段辅助判断？

建议回答：

> 目前我们有 Event 行为数据，可以间接捕捉一部分热度变化，但还没有直播、节日、订货会、主推等特殊业务节点字段。因此模型对已经发生并体现在行为数据里的热度有一定感知，但对未来计划活动无法提前知道。

为什么重要：

```text
直播/主推 -> 短期爆发，容易低估
节日/订货会 -> 集中订货，普通历史均值难解释
活动结束 -> 需求回落，容易误补
```

建议甲方提供特殊节点日历：

```text
event_id
event_name
event_type
event_start_date
event_end_date
scope_style_id
scope_sku_id
scope_category
scope_channel
event_strength
planned_exposure
planned_discount
actual_exposure
actual_order_qty
```

注意说清楚：

> 预测日前已经计划好的活动可以作为预测特征；活动后才知道的真实曝光和真实订单只能用于复盘，不能作为预测时特征。

## 6. 可能被问到的问题

### Q1：Phase8 是否已经正式替代 Phase7？

答：

> Phase8 已经可以作为当前阶段候选主线定版，但工程上建议保留 Phase7 作为 fallback。对外可以说 Phase8 在多锚点评估中整体优于 Phase7，后续等 6 月完整标签后做定版后监控。

### Q2：为什么 6.16 最新数据不同步重训？

答：

> 6.16 快照只比 6.14 多两天，而且未来 30 天标签还不完整。现在强行评估会系统性低估真实补货，所以先完成数据注册和审计，等标签完整后再做监控验证。

### Q3：盈亏模块能不能直接上线用？

答：

> 目前可以作为 V1 原型和决策辅助模块，但不是正式自动下单系统。上线前还需要真实成交价、生产周期、在途订单、成本覆盖和人工决策反馈。

### Q4：商品识别量化是不是要重新做一个视觉模型？

答：

> 第一阶段不建议重做复杂视觉模型。更合理的是先用多模态 API 做结构化打标，再人工复核，形成稳定商品基因表，把标签作为冷启动特征和相似款检索依据。后续如果积累到几千个历史商品、稳定图片、人工复核标签和销售/补货结果，再考虑训练或微调视觉模型。

### Q5：特殊节点现在能不能解决？

答：

> 现在只能部分间接解决，因为 Event 行为能反映热度变化，但不能提前知道计划直播或节日活动。要真正解决，需要甲方提供特殊节点日历和活动影响范围。
