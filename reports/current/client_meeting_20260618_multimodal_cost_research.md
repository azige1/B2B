# 引入多模态商品识别的成本调研

日期：2026-06-17  
用途：6.18 甲方会议补充材料  
汇率假设：`1 USD ~= 7.2 RMB`，仅用于粗估，实际以结算日为准。

## 1. 结论

如果只是处理甲方当前提到的 `260 个 SKU`，多模态 API 本身的费用很低，通常不是主要成本。

真正的成本排序大致是：

```text
人工复核成本 > 工程接入成本 > 数据治理/合规成本 > API调用成本 > 存储成本
```

建议对外口径：

> 260 个 SKU 规模下，先做多模态 API 打标 + 人工复核是成本可控的。API 调用费通常只是几十到几百元人民币级别；真正需要投入的是标签体系设计、人工复核、批处理脚本、质量审计和后续与预测模型的对齐实验。当前不建议直接训练视觉模型，训练路线要等历史商品和人工标签积累到几千个以上再考虑。

## 2. 成本构成

### 2.1 一次性 API 打标成本

成本取决于：

```text
SKU 数量
每个 SKU 图片数量
图片分辨率
是否每张图单独调用
输出 JSON 长度
是否做多轮/多模型交叉校验
```

当前建议基准：

```text
SKU = 260
图片 = 5 张 / SKU
总图片 = 1,300 张
输出 = 结构化 JSON，约 500-1000 tokens / SKU
调用方式 = 每个 SKU 一次请求，输入多张图，输出一个 JSON
```

### 2.2 人工复核成本

人工复核是为了让标签体系稳定，而不是完全相信模型描述。

常见复核强度：

| 复核方式 | 时间假设 | 总耗时 | 适用场景 |
| --- | ---: | ---: | --- |
| 抽检 | 20%-30% SKU，每个 2-3 分钟 | 2-4 小时 | 只做技术 demo |
| 常规复核 | 260 个 SKU，每个 2-4 分钟 | 9-18 小时 | 推荐 V1 |
| 精细复核 | 260 个 SKU，每个 6-10 分钟 | 26-43 小时 | 作为正式商品基因表 |

如果按 `80-200 RMB/小时` 的商品/设计助理复核成本估算：

| 复核方式 | 人工成本粗估 |
| --- | ---: |
| 抽检 | 160-800 RMB |
| 常规复核 | 720-3,600 RMB |
| 精细复核 | 2,080-8,600 RMB |

如果需要资深设计/企划人员确认细粒度设计语言，成本会更高，建议按 `200-500 RMB/小时` 单独估。

### 2.3 工程接入成本

工程成本比 API 费用更重要。

| 阶段 | 工作内容 | 人天估计 |
| --- | --- | ---: |
| V0 demo | prompt/schema、批量调用、CSV 输出、失败重试 | 1-2 人天 |
| V1 入库 | 标签字典、审计表、人工复核表、版本管理 | 3-7 人天 |
| V2 预测接入 | 特征 join、相似款检索、冷启动 shadow 实验 | 5-10 人天 |
| V3 平台化 | 权限、前端、任务队列、增量打标、监控 | 15+ 人天 |

如果内部工程人天按 `1000-3000 RMB/天` 粗估：

| 阶段 | 工程成本粗估 |
| --- | ---: |
| V0 demo | 1,000-6,000 RMB |
| V1 入库 | 3,000-21,000 RMB |
| V2 预测接入 | 5,000-30,000 RMB |
| V3 平台化 | 15,000 RMB 以上 |

### 2.4 存储和向量检索成本

260 个 SKU 规模很小。

假设：

```text
每 SKU 5 张图
每张图 1-3 MB
总图片 1,300 张
总大小约 1.3-3.9 GB
```

成本判断：

- 本地存储：基本可以忽略；
- 普通对象存储：通常是个位数到几十 RMB/月；
- 本地 FAISS/Annoy 向量检索：免费；
- 托管向量数据库：一般从百元级/月起，不建议一开始就上。

## 3. API 费用估算

### 3.1 官方价格依据

当前查到的官方价格和计费规则：

- OpenAI API：图片会转成 token 计费，文本模型按标准文本 token 价格收取；官方价格页的图片计算器示例显示 512x512 低分辨率图片约 210 tokens，示例价约 `$0.000263` / 张。  
  来源：https://openai.com/api/pricing/  
  来源：https://developers.openai.com/api/docs/guides/images-vision

- Google Gemini：Gemini 2.5 Flash 标准价为输入 `$0.30 / 1M tokens`、输出 `$2.50 / 1M tokens`；Gemini 2.5 Flash-Lite 标准价为输入 `$0.10 / 1M tokens`、输出 `$0.40 / 1M tokens`，Batch/Flex 更低。  
  来源：https://ai.google.dev/gemini-api/docs/pricing

- Alibaba Qwen-VL：`qwen-vl-plus` 为输入 `$0.21 / 1M tokens`、输出 `$0.63 / 1M tokens`；`qwen-vl-max` 为输入 `$0.8 / 1M tokens`、输出 `$3.2 / 1M tokens`；单图最高可到 16,384 tokens。  
  来源：https://www.alibabacloud.com/help/en/model-studio/models

- Anthropic Claude Vision：官方文档给出 1000x1000 图片约 1296 tokens，Sonnet 价位下约 `$0.0039` / 张，约 `$3.89` / 1000 张；更高阶 Opus 价位更高。  
  来源：https://platform.claude.com/docs/en/build-with-claude/vision

价格会变化，会议上不要把具体价格说死，应说“按 2026-06-17 官方页粗估”。

### 3.2 260 SKU 一次打标粗估

统一假设：

```text
SKU = 260
图片 = 5 张 / SKU
总图片 = 1,300
每个 SKU 输出 JSON = 700 tokens
每个 SKU 文本 prompt/schema = 800 tokens
```

#### 方案 A：低成本 API 路线

模型类似：

```text
Gemini 2.5 Flash-Lite
Qwen-VL-Plus
OpenAI mini级视觉模型
```

粗估：

| 项 | 成本级别 |
| --- | ---: |
| API 输入图片+文本 | 通常 < 1-10 USD |
| API 输出 JSON | 通常 < 1-5 USD |
| 折合人民币 | 约 10-100 RMB 内 |

实际很可能比这个更低，尤其使用 batch 或低分辨率图片时。

#### 方案 B：稳健 API 路线

模型类似：

```text
Qwen-VL-Max
Gemini Flash/Pro
OpenAI 更强视觉模型
Claude Sonnet
```

粗估：

| 项 | 成本级别 |
| --- | ---: |
| API 输入图片+文本 | 约 5-50 USD |
| API 输出 JSON | 约 2-20 USD |
| 折合人民币 | 约 50-500 RMB |

对 260 SKU 来说仍然不贵。

#### 方案 C：双模型交叉校验

做法：

```text
模型A打标
模型B复核或二次打标
标签冲突项交给人工
```

成本约为单模型的 `2x`，但仍然通常低于人工复核成本。

适用场景：

- 标签体系刚建立；
- 甲方对标签准确性要求高；
- 需要找出模型不确定的商品。

## 4. 最现实的 V0/V1 总成本

### 4.1 V0 技术 demo

目标：

```text
证明 260 SKU 可以被打成结构化商品基因表
输出可读 CSV/Excel
抽检标签质量
```

成本：

| 成本项 | 粗估 |
| --- | ---: |
| API | 10-300 RMB |
| 人工抽检 | 200-1000 RMB |
| 工程 | 1-2 人天 |
| 总体 | 约 1,000-8,000 RMB，主要看工程人天是否计入 |

### 4.2 V1 可入库版本

目标：

```text
标签字典稳定
人工复核闭环
可重复批量打标
能接入预测模型 shadow 实验
```

成本：

| 成本项 | 粗估 |
| --- | ---: |
| API | 50-500 RMB |
| 人工复核 | 1,000-8,000 RMB |
| 工程 | 3-7 人天 |
| 数据审计/字典整理 | 1-3 人天 |
| 总体 | 约 1万-5万 RMB 级别 |

### 4.3 V2 接入预测模型

目标：

```text
商品基因表入库
构造冷启动特征
相似款生命周期曲线
跑 shadow 实验
验证是否提升 WMAPE / 大货少补 / 冷启动指标
```

成本：

| 成本项 | 粗估 |
| --- | ---: |
| API/复核增量 | 低 |
| 工程与实验 | 5-10 人天 |
| 分析报告 | 1-2 人天 |
| 总体 | 约 2万-8万 RMB 级别，取决于是否做前端/报表 |

## 5. 训练或微调的成本

当前不建议直接训练视觉模型。

### 5.1 为什么 260 SKU 不适合训练

原因：

- 样本太少；
- 标签体系还不稳定；
- 训练目标不清楚，是识别标签、找相似款，还是预测销量；
- 服装销售结果受价格、渠道、活动、买手、库存影响，图片不是唯一原因；
- 直接用图片预测销量容易过拟合。

### 5.2 什么时候可以考虑训练

建议门槛：

```text
历史商品 >= 2,000-5,000 个 style/SKC
图片 >= 10,000 张
人工复核标签覆盖主要类目
有补货/销售/售罄/库存/退货结果
标签字典稳定
```

### 5.3 训练成本粗估

训练路线主要成本不是 GPU，而是数据和工程。

| 成本项 | 小规模微调 | 正式模型 |
| --- | ---: | ---: |
| 人工标签 | 2万-10万 RMB | 10万+ RMB |
| 工程 | 2-4 周 | 1-3 月 |
| GPU/云算力 | 几百-几千 RMB | 几千-数万 RMB |
| 评估与迭代 | 1-2 周 | 持续 |
| 总体 | 5万-20万 RMB | 20万-50万+ RMB |

更实际的训练任务：

1. 训练标签分类器  
   让模型稳定识别颜色、版型、面料、结构、风格等。

2. 微调相似款 embedding  
   让设计语言相近、生命周期曲线相近的商品向量更近。

3. 不建议第一步做端到端销量预测  
   因为销量/补货受业务变量影响太多，图片信号只是其中一部分。

## 6. 数据安全和合规成本

这是隐藏成本，尤其是新品设计图。

### 6.1 外部 API 风险

如果商品图片是未上市款或设计稿，风险包括：

- 款式泄露；
- 设计资产被第三方处理；
- 跨境传输或供应商合规问题；
- 甲方内部是否允许使用外部模型 API。

OpenAI 官方文档说明 API 数据默认不用于训练，除非显式选择共享数据；Google Gemini 付费层说明内容不用于改进产品，而免费层可能用于改进产品。  
来源：https://developers.openai.com/api/docs/guides/your-data  
来源：https://ai.google.dev/gemini-api/docs/pricing

会议建议：

> 如果甲方图片涉及未上市设计，建议使用付费 API、企业条款或国内云服务，并在输入中去除不必要的敏感信息。若甲方要求严格内网，则考虑本地/私有化部署开源视觉模型，但工程成本会明显上升。

### 6.2 私有化方案成本

私有化方式：

```text
本地部署 Qwen-VL / InternVL / CLIP 类模型
本地对象存储图片
本地向量库 FAISS
不把图片发给外部 API
```

成本判断：

| 项 | 成本 |
| --- | ---: |
| GPU 临时跑批 | 几十到几百 RMB 级别 |
| 本地开发调试 | 3-10 人天 |
| 长期服务 | 需要 GPU 服务器或云 GPU，百到千元/月以上 |
| 模型效果 | 通常不如最强闭源多模态 API 稳定 |

私有化适合：

- 图片高度敏感；
- 不能跨境；
- 后续规模大；
- 甲方愿意承担更多工程成本。

不适合：

- 只是 260 SKU 的 V0 验证；
- 需要最快出结果；
- 没有 GPU/部署条件。

## 7. 推荐预算方案

### 7.1 最推荐：低成本可验证方案

```text
多模态 API + 人工复核 + 本地 CSV/Excel
```

预算：

```text
API：< 500 RMB
人工复核：1,000-5,000 RMB
工程：3-5 人天
总成本：约 1万-3万 RMB 级别
```

产出：

- 260 SKU 商品基因表；
- 标签字典；
- 低置信度/冲突标签清单；
- 相似款检索 demo；
- 是否适合接入预测模型的初步判断。

### 7.2 稳健业务验证方案

```text
双模型打标 + 人工复核 + 入库 + 冷启动 shadow 实验
```

预算：

```text
API：< 1000 RMB
人工复核：3,000-10,000 RMB
工程/实验：7-15 人天
总成本：约 3万-8万 RMB 级别
```

产出：

- 可重复打标 pipeline；
- 商品基因表入库；
- 相似款生命周期曲线；
- 冷启动预测增益报告；
- 是否进入 Phase9 的决策依据。

### 7.3 不建议现在做：训练视觉模型

预算：

```text
5万-20万 RMB 起步
```

问题：

- 当前 260 SKU 不够；
- 标签体系未稳定；
- 业务结果样本少；
- 成本高但不一定有增益。

## 8. 会议建议口径

可以这样讲：

> 多模态的直接 API 成本并不高。以 260 个 SKU、每个 3-5 张图计算，API 打标大概率是几十到几百元人民币级别，主要成本不在 token，而在人工复核、标签体系设计、工程接入和数据安全。我们建议先做 API 打标 + 人工复核的 V1 商品基因表，用它验证冷启动和相似款生命周期是否有增益；不建议现在直接训练视觉销量模型，因为 260 个 SKU 样本太少，训练成本和过拟合风险都高。

如果甲方关心预算，可以给三档：

| 档位 | 内容 | 粗估 |
| --- | --- | ---: |
| Demo | API 打标 + 抽检 + CSV | 1,000-8,000 RMB |
| V1 | API + 人工复核 + 入库 + 审计 | 1万-5万 RMB |
| V2 | V1 + 相似款 + 预测 shadow 实验 | 3万-8万 RMB |

## 9. 需要甲方确认

会议上要问：

1. 商品图片是否允许发给外部多模态 API？
2. 是否要求国内云或私有化部署？
3. 260 个 SKU 是否有主图、细节图、模特图和平铺图？
4. 是否有历史老款图片，能用于相似款检索？
5. 商品标签是否由甲方定义，还是先由我们给一版标签字典？
6. 是否有设计/企划人员参与复核？
7. 最先验证的目标是冷启动预测，还是企划复盘/防撞款演示？
